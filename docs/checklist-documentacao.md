# Checklist de Qualidade da Documentação

Use este checklist antes de considerar a documentação pronta.

## Visão geral

- [ ] O objetivo do projeto está explicado.
- [ ] O escopo e as principais funcionalidades estão descritos.
- [ ] Os públicos ou usuários previstos estão identificados.

## Ambiente e execução

- [ ] Tecnologias e versões relevantes estão listadas.
- [ ] Pré-requisitos estão descritos.
- [ ] Instalação e configuração seguem uma sequência clara.
- [ ] Os comandos foram testados em um ambiente compatível.
- [ ] A execução e o acesso à aplicação estão explicados.

## Qualidade técnica

- [ ] Estrutura do projeto está descrita.
- [ ] Testes existentes têm instruções de execução.
- [ ] APIs e dados de entrada/saída estão documentados, quando aplicável.
- [ ] Diagramas representam a arquitetura atual, quando necessários.
- [ ] Processo de CI/CD e deploy está explicado, quando aplicável.

## Segurança e manutenção

- [ ] Não há senhas, tokens, chaves ou dados sensíveis.
- [ ] Exemplos de configuração usam valores fictícios.
- [ ] Links estão funcionando.
- [ ] A documentação corresponde ao comportamento atual do código.
- [ ] Existe orientação para contribuição ou comunicação de problemas, quando aplicável.

## Teste final

Peça a alguém que não desenvolveu o projeto para seguir o README. Registre as dúvidas e corrija as instruções que não forem claras.
