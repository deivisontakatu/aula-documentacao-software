# Política de Segurança

## Objetivo

Este repositório é destinado a materiais didáticos sobre documentação de software. Mesmo em projetos educacionais, relatos de vulnerabilidade devem ser tratados com responsabilidade.

## Versões contempladas

Como este repositório é principalmente documental, não há garantia de que exemplos didáticos representem aplicações prontas para produção. Caso um exemplo seja utilizado em uma aplicação real, a pessoa responsável por essa aplicação deve avaliar e corrigir seus próprios riscos.

## Como relatar uma vulnerabilidade

- **Não** publique senhas, tokens, chaves, dados pessoais ou detalhes exploráveis em Issues ou Pull Requests públicos.
- Se o GitHub disponibilizar a opção **Report a vulnerability** na aba Security, utilize o canal privado.
- Se essa opção não estiver disponível, entre em contato com a pessoa responsável pelo repositório por um canal privado do GitHub, sem divulgar publicamente os detalhes técnicos sensíveis.
- Inclua uma descrição objetiva, o impacto potencial e passos seguros para reproduzir o problema, quando possível.

## O que evitar

- Não teste vulnerabilidades contra sistemas ou contas de terceiros sem autorização.
- Não publique provas de conceito que exponham dados ou facilitem exploração antes de uma correção.
- Não envie credenciais reais. Use exemplos fictícios.

## Tratamento dos relatos

Os relatos serão analisados conforme a disponibilidade e a natureza do projeto. Como este é um repositório educacional, não há prazo formal de resposta nem garantia de suporte a aplicações derivadas.

## Escopo

Esta política cobre o conteúdo mantido neste repositório. Projetos criados a partir dos exemplos precisam estabelecer e manter sua própria política de segurança.
